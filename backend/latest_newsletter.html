今日技术早报：GPT-6 发布、OpenAI 数学突破、Vercel AI SDK 更新

AI 正在重塑交互、科研与企业工作流，而工具链的进化让开发者站上了浪潮之巅。

🔥 AI 前沿

GPT-6 全球发布，带来 Intelligent UI

深度看点：
- GPT-6 在全球范围内向 ChatGPT 用户推送，核心升级在于 Intelligent UI——不再是纯文本对话，而是根据上下文动态生成可视化与交互式体验。
- 响应速度进一步提升，同时支持“探索并使用”直接在对话中生成的交互组件。
- 这意味着模型输出从“文本流”进化为“可操作的界面”，对前端交互设计范式产生直接冲击。

极客点评：
Intelligent UI 的本质是 LLM 输出结构化 UI 描述 + 前端运行时渲染。对开发者而言，未来 AI 应用的竞争力不再只是 prompt 调优，而是如何设计一套可靠的“模型输出 → UI 组件”映射层。建议关注 OpenAI 是否开放对应的结构化输出 schema，这将决定你能否在自己的产品中复现类似体验。

OpenAI 用未发布的前沿模型解决数百个数学开放问题

深度看点：
- OpenAI 发布了 722 篇手稿，覆盖 372 个结果族（将相关论文分组的集合），包含对“数百个”长期开放数学问题的解答。
- 这些结果由一个 未发布的前沿模型 产出，OpenAI 声称“平均每个结果”消耗约 3 小时 ChatGPT Pro 级别的推理算力。
- 发布通过 GitHub 仓库进行，包含论文修订与引用协议，同时附带了部分模型推理摘要和算力估算。
- 独立数学家咨询组 AGMAI 同步发布建议，呼吁 AI 实验室 不要将数学成果发布当作模型营销工具，并应披露模型名称、prompt 和算力成本。

极客点评：
这条新闻的技术信号远大于数学本身：前沿模型的推理算力正在被系统性地用于科学发现。3 小时 Pro 级推理约等于大量 CoT、搜索与验证循环，这套 pipeline 对做 AI4Science 的团队有直接参考价值。但 AGMAI 的警告同样值得重视——当 AI 产出的学术成果缺乏可追溯的 prompt 和算力披露时，可复现性就无从谈起。如果你在做科研类 AI 产品，从第一天就设计好审计日志和引用链路，否则后期补课成本极高。

Atlassian 与 OpenAI 扩大合作，将企业知识转化为行动

深度看点：
- 合作核心是将 前沿模型与企业知识库 直接连接，覆盖规划、构建、交付的完整工作流。
- 目标场景是让团队在 Jira、Confluence 等工具中直接调用模型能力，而非在独立聊天窗口中操作。

极客点评：
这是 RAG + Agent 在企业场景的标准落地路径：知识源（Confluence）→ 检索 → 推理 → 动作（Jira 工单、PR、部署）。对开发者的启示是，企业 AI 集成的壁垒不在模型本身，而在 权限模型、数据隔离和操作审计。如果你在构建类似集成，优先解决“模型能看什么、能改什么、改了怎么追溯”这三个问题。

OpenAI 与 Ironclad 推进专业合同工作流中的 Computer Use Agent

深度看点：
- 双方合作训练和评估 AI Agent 在 复杂合同工作流 中的计算机使用能力。
- 重点在于让 Agent 操作真实软件界面完成专业任务，而非仅生成文本建议。

极客点评：
Computer Use Agent 的难点从来不是“能不能点按钮”，而是 在长流程中保持状态一致性和错误恢复。合同工作流的特点是步骤多、依赖强、容错低，这正是检验 Agent 可靠性的理想场景。建议关注他们是否公开评估基准——如果有，这将成为衡量 Computer Use 方案成熟度的关键标尺。

🚀 开源框架动向

Vercel AI SDK @ai-sdk/typesafe-ai@3.0.16 发布

深度看点：
- 实验性决策状态新增有序的 text、file、JSON 部分，支持在 OpenAI Decisions 和语言模型适配器中传入图像输入。
- 状态归一化：所有公开状态形式在调用决策提供者前统一转为 parts 数组；直接传数组作为 state 时现在会包含 decision state parts，JSON 数组需包裹在对象或 json part 中。
- OpenTelemetry 集成：decision file 字节以 base64 序列化到 OTel state 属性中；模型调用 span 记录归一化后的 state parts，外层 span 保留公开 state 输入。
- Gateway 和 TypeSafe AI 仍拒绝文件输入，保持原有 string/JSON 请求格式。

极客点评：
这次更新的核心是 为多模态 Agent 状态管理建立统一抽象。text | file | json 的 ordered parts 模型实际上是在定义一套“决策上下文”的标准数据结构，这对构建可观测、可回放的 Agent 系统至关重要。注意破坏性变更：如果你之前直接传 JSON 数组作为 state，现在必须包裹成对象或 json part，否则会触发错误。OTel 的 base64 文件序列化对调试多模态链路很有用，但要注意大文件对 tracing 后端存储的压力。
