# 00 · 总览与系统架构规划

## 一、架构选型核心决策：计算放前端 vs 数据库配置

### 1. 核心结论
采用 **「纯前端本地毫秒级计算 + 动态政策配置云端同步/本地兜底缓存」** 的混合架构（Hybrid Architecture）。

### 2. 决策权衡分析

| 维度 | 方案 A：纯后端/云函数计算 | 方案 B：纯前端写死全部配置 | 方案 C：前端计算 + 数据库配置（选用） |
| :--- | :--- | :--- | :--- |
| **交互体验** | 每次滑块变动需等网络响应（300-1000ms），体验卡顿 | 0ms 即时响应，极其丝滑 | **0ms 本地即时响应，拖动滑块无缝刷新** |
| **离线可用** | 弱网/无网/飞行模式不可用 | 支持离线使用 | **离线使用本地默认配置，有网自动增量同步** |
| **政策更新时效** | 随时修改接口参数，秒级生效 | 需重新发版提交微信审核（耗时1-3天） | **云数据库一键改参数，全国用户秒级生效无需发版** |
| **云资源成本** | 频繁调用消耗云函数配额与并发限制 | 0 成本 | **仅在启动时检查版本号（1次请求），近乎零成本** |
| **用户隐私安全** | 收入、房贷、资产等敏感数据需上云 | 数据不出手机，隐私安全 | **敏感数据完全留存本地，仅下载公开政策基准** |

## 二、三层技术架构设计

```
┌────────────────────────────────────────────────────────┐
│                   前端展示与交互层                      │
│   (miniprogram/pages/: index, result, compare, poster) │
└───────────────────────────▲────────────────────────────┘
                            │ 调用纯函数 / 传入参数
┌───────────────────────────┴────────────────────────────┐
│                    算法引擎核心层                       │
│              (miniprogram/utils/calculators/)           │
│   - 纯函数设计，无 DOM/UI 依赖，输入输出结构化         │
│   - 覆盖 67 个专业计算模型与最优求解算法               │
└───────────────────────────▲────────────────────────────┘
                            │ 读取基准参数 (税率、LPR、调休)
┌───────────────────────────┴────────────────────────────┐
│                  政策与基准配置中心                     │
│                (miniprogram/utils/config/)              │
│   - 本地内嵌保底配置 (Local Fallback Constants)        │
│   - 启动时后台校验云数据库版本号 (wx.cloud / Storage)  │
└────────────────────────────────────────────────────────┘
```
